1. OBIETTIVO E VISIONE DEL PROGETTO
--------------------------------------------------------------------------------
Il progetto e' il sito personale e portfolio ingegneristico di Gioele Rora,
sviluppato come piattaforma web moderna, scalabile, esteticamente avanzata
e ottimizzata per recruiter tecnici, docenti universitari, aziende tech
e colleghi sviluppatori.

Obiettivi primari:
1. Personal Branding ad alto impatto visivo e tecnico: rappresentare l'identita'
   di Gioele (Ingegneria Informatica al Politecnico di Torino, membro IEEE-HKN,
   firmware engineer in Team Astra, membro Team QubiTo).
2. Showcase Tecnico Dettagliato: presentare progetti reali e verificabili
   (Edge-AI, simulazioni fisiche 3D, piattaforme web full-stack), corredati da
   schede architetturali, sfide ingegneristiche risolte, gallerie fotografiche e
   screenshot autentici, video dimostrativi e repository ufficiali.
3. Curriculum Vitae accessibile e scaricabile: versione web strutturata per
   lettura rapida, sincronizzata con il PDF ufficiale scaricabile in un clic
   (pubblicato in /public/cv-gioele.pdf) e ottimizzata per la stampa cartacea.
4. Architettura Zero-Cost & Massime Performance: nessun server proprietario da
   mantenere acceso; dati gestiti in locale in formato TypeScript tipizzato;
   compilazione statica (SSG/PPR) con hosting serverless edge su Vercel a costo zero.

4. ARCHITETTURA DI GESTIONE DEI DATI (LOCAL-FIRST)
--------------------------------------------------------------------------------
Il sito adotta un'architettura dati statica locale tipizzata (Local-First Static Data):
- Nessun database relazionale o backend server attivo in esecuzione continua.
- Tutti i dati risiedono in file TypeScript dedicati all'interno di `src/data/`:
  * `src/data/profile.ts`: anagrafica, bio, contatti, link social, highlight.
  * `src/data/skills.ts`: competenze tecnologiche per categorie con livelli.
  * `src/data/projects.ts`: schede complete, architettura, sfide tecniche, gallerie e repository.
  * `src/data/cv.ts`: esperienze lavorative, percorso accademico, certificazioni, lingue.
- I tipi corrispondenti sono definiti rigorosamente in `src/types/`:
  * `src/types/profile.ts`
  * `src/types/skill.ts`
  * `src/types/project.ts`
  * `src/types/cv.ts`
- Vantaggi per il progetto:
  * Zero costi di server e hosting.
  * Massima velocita' di caricamento: tutte le pagine vengono prerenderizzate
    durante la build (`next build`) in HTML/CSS statico distribuito su CDN.
  * Aggiornabile modificando semplicemente i file dati e facendo push su GitHub.

9. GUIDA PER QUALSIASI AI O SVILUPPATORE (REGOLE DI MODIFICA)
--------------------------------------------------------------------------------
Se stai modificando questo progetto, rispetta scrupolosamente queste linee guida:

1. Zero Dati Finti (No Placeholder):
   Non inserire mai progetti inventati, aziende fantasma o testi "Lorem Ipsum".
   Ogni dato deve rispecchiare esclusivamente le competenze reali e le attivita'
   effettive di Gioele Rora.

2. Lingua del Progetto:
   - Tutti i testi visibili agli utenti sul sito (UI, schede, pulsanti, titoli)
     devono essere rigorosamente in lingua INGLESE (`en`).
   - La documentazione interna puo' essere in italiano o inglese.

3. Come aggiungere un nuovo Progetto:
   - Aggiungi un nuovo oggetto `ProjectItem` all'array `projectsData` in `src/data/projects.ts`.
   - Inserisci eventuali screenshot nella cartella `public/projects/`.
   - La pagina `/progetti/[slug]` e la scheda in `/progetti` verranno create
     automaticamente alla build successiva grazie a `generateStaticParams`.

4. Come aggiornare il Curriculum Vitae:
   - Sostituisci il file PDF in `public/cv-gioele.pdf`.
   - Aggiorna i dati testuali corrispondenti in `src/data/cv.ts` per mantenere
     il CV web perfettamente allineato al PDF scaricabile.

5. Come aggiornare competenze o bio:
   - Modifica `src/data/skills.ts` o `src/data/profile.ts`.
   - Tutti i componenti della Home Page e delle sottopagine attingono direttamente
     da questi file dati.

6. Flusso Git e Deploy:
   - Esegui sempre `npm run build` prima di committare per verificare che non
     ci siano errori TypeScript o di compilazione.
   - Effettua commit atomici e descrittivi seguendo la convenzione Conventional Commits:
     * `feat(...)`: nuova funzionalita' o contenuto.
     * `fix(...)`: correzione di bug o refuso.
     * `docs(...)`: aggiornamento della documentazione.
     * `style(...)`: modifiche puramente estetiche o CSS.
   - Il comando `git push origin main` avvia automaticamente il deploy su Vercel.
